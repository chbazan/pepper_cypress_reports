Descripción detallada

El test ejecutaba la validación de la cotización de cierre para el bono RESA15, comparando el valor de la UI contra la API de Appraiser. El fallo ocurrió después de que una solicitud POST a la API `/appraiser` devolviera un status 200 OK. La evidencia del stack trace muestra un `TypeError: Cannot read properties of null (reading 'money')` dentro de un comando custom de Cypress, lo que indica que el código del test intentó acceder a la propiedad 'money' de un objeto que era `null` en la respuesta de la API.

Posibles causas

ALTA
Respuesta de API Appraiser con estructura inesperada o `null`.
El error es un `TypeError` en el código del test al procesar la respuesta, no un fallo de red. El HAR confirma que la request a `/appraiser` tuvo un status `200 OK`, lo que apunta a un problema en el contenido (body) de la respuesta.
MEDIA
Datos de entrada para la valuación del bono RESA15 son incorrectos.
Es posible que los datos enviados en el `POST` a `/appraiser`, aunque válidos para la API (no devolvió 4xx), hayan provocado que el motor de cálculo no encuentre un precio y devuelva una respuesta válida pero vacía o nula.
BAJA
Bug en el custom command de Cypress (`cotizaciones.commands.js`).
El comando podría tener un error en el manejo de casos borde para respuestas válidas pero sin datos. Sin embargo, es más probable que el problema esté en los datos de la API, ya que los comandos suelen ser estables.

Pasos de Troubleshooting

1 Reproducir el spec fallido para confirmar la intermitencia: `TARGET_ENV=production TARGET_CLIENT=br-gs32 MODE=only SPEC=cotizaciones_cierre_br npm run test`
2 Inspeccionar el HAR del fallo para encontrar la request `POST` al endpoint `/appraiser`.
3 Copiar la request como cURL desde el HAR y ejecutarla en una terminal para inspeccionar el response body detalladamente.
4 Verificar si el response body contiene un objeto con la propiedad `money` o si devuelve `null` o un array vacío.
5 Consultar con el equipo de backend sobre el comportamiento esperado de la API `/appraiser` para el bono RESA15 con los parámetros usados en el test.
6 Revisar el código del comando en `cypress/support/commands/cotizaciones.commands.js` en la línea 558 para añadir un manejo defensivo contra respuestas nulas si se considera un caso válido.
