Timeout al buscar ticker RESA15 en cotizaciones de cierre - elemento de refresh no encontrado

Descripción detallada

El test 'Guardar la cotización de cierre del ticker RESA15' intentaba guardar una cotización de cierre para el ticker RESA15 en el módulo de administración de cotizaciones de securities para Brasil. El fallo ocurrió cuando el test esperaba encontrar el elemento `span.glyphicon-refresh`, probablemente un indicador de carga, pero no lo encontró tras 60000ms. La UI mostraba un mensaje de advertencia 'RESA15 no encontrada en tabla -- retry' y 'No hay información para mostrar', a pesar de que el resumen de red no reporta requests fallidos o lentos. La duración total del test fue de 87810ms, excediendo el timeout del comando.

Posibles causas

ALTA
Datos no encontrados/renderizados para RESA15
El screenshot muestra claramente 'RESA15 no encontrada en tabla -- retry' y 'No hay información para mostrar', indicando que el ticker no se cargó o no existe en la tabla, lo que causó que el elemento de refresh no se comportara como esperado.
MEDIA
Problema de sincronización UI/Backend
Aunque no hay errores de red reportados, la UI no se actualiza con los datos esperados. Podría haber un problema en el procesamiento de la respuesta del backend por parte del frontend o un retraso en la actualización del DOM que no se refleja en los logs de red.
BAJA
Selector `span.glyphicon-refresh` obsoleto o incorrecto
Es menos probable, pero el selector `span.glyphicon-refresh` podría haber cambiado o ya no ser el indicador de carga correcto para esta funcionalidad, aunque la evidencia de 'RESA15 no encontrada' apunta a un problema de datos más fundamental.

Pasos de Troubleshooting

1 Reproducir el spec fallido localmente: `TARGET_ENV=production TARGET_CLIENT=br-gs32 MODE=only SPEC=cotizaciones_cierre_br.cy.js npm run test`
2 Verificar manualmente en `admin.brasil.mercap.com.ar/administrative` si el ticker RESA15 existe y se puede buscar en la sección 'Administrar cotizaciones de securities' en el ambiente de producción de Brasil.
3 Inspeccionar el HAR para el request que debería traer los datos de RESA15 y verificar el cuerpo de la respuesta (incluso si es 200 OK) para ver si contiene datos vacíos o un mensaje de error lógico.
4 Si el ticker existe y la API devuelve datos, revisar el código frontend (específicamente `cotizaciones.commands.js:231`) para entender cuándo se espera que aparezca/desaparezca `span.glyphicon-refresh` y cómo se renderizan los datos en la tabla.
