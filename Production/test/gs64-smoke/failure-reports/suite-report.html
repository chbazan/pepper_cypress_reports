Timeout al buscar botón 'Editar' en Calendarios - elemento no encontrado

Descripción detallada

El test intentaba recorrer los calendarios y hacer click en el botón 'Editar' para cada uno. El fallo ocurrió en el paso donde Cypress intentó encontrar el elemento `button[name='Editar']` dentro de la primera fila de la tabla (`@fila`). El comando `cy.get(@fila).find('button[name="Editar"]')` agotó su `defaultCommandTimeout` de 60000ms sin encontrar el elemento. El video muestra que la página de Calendarios cargó correctamente y la tabla con los calendarios 'Local' y 'Default' es visible, pero el botón 'Editar' no aparece en la fila incluso después de un `mouseover`.

Posibles causas

ALTA
Botón 'Editar' no renderizado/visible
El error `Expected to find element: button[name="Editar"], but never found it` y la duración exacta de 60000ms confirman que el elemento no apareció en el DOM o no fue visible dentro del timeout. El video muestra que el mouseover no hizo aparecer el botón.
MEDIA
Selector `button[name="Editar"]` obsoleto
Un cambio en la implementación del botón podría haber alterado su `name` atributo o la forma en que se identifica, haciendo que el selector actual no lo encuentre.
BAJA
Problema de interacción con `mouseover`
Aunque el test ejecuta `trigger('mouseover')`, el video sugiere que el evento no tuvo el efecto esperado de mostrar el botón, lo que podría indicar un bug en la aplicación o un problema con la simulación del evento.

Pasos de Troubleshooting

1 Abrir la aplicación manualmente en `production/br-gs64` y navegar a Calendarios.
2 Verificar si el botón "Editar" aparece al hacer `mouseover` sobre las filas de la tabla.
3 Inspeccionar el DOM de la tabla de Calendarios para verificar el selector `button[name="Editar"]` y su visibilidad.
4 Reproducir el spec fallido localmente: `TARGET_ENV=production TARGET_CLIENT=br-gs64 MODE=only SPEC=gs64_smoke_calendarios npm run test`

Elemento de tabla de Tasas cubierto por modal 'Alta de Tasa'

Descripción detallada

El test intentaba recorrer las tasas y hacer click en el botón 'Editar' para cada una. El fallo ocurrió cuando Cypress intentó ejecutar `cy.trigger()` en un elemento de fila de la tabla (`<tr class='table-body-row'>`), pero este estaba cubierto por el modal 'Alta de Tasa'. El comando agotó su `defaultCommandTimeout` de 60000ms. El video y el screenshot confirman que el modal 'Alta de Tasa' está abierto y bloqueando la interacción con la tabla subyacente.

Posibles causas

ALTA
Modal 'Alta de Tasa' se abre inesperadamente
El mensaje de error y el screenshot/video muestran claramente que un modal está cubriendo el elemento. Esto sugiere que un paso previo del test o un evento inesperado en la aplicación provocó la apertura del modal.
MEDIA
Fallo en el cierre de un modal previo
Si el test intentó crear o editar una tasa antes y el modal de creación/edición no se cerró correctamente, podría persistir y bloquear acciones posteriores.
BAJA
Problema de renderizado de la UI
Menos probable, pero un bug de UI podría hacer que el modal aparezca sin una acción explícita del usuario o del test.

Pasos de Troubleshooting

1 Abrir la aplicación manualmente en `production/br-gs64` y navegar a Tasas.
2 Verificar si el modal 'Alta de Tasa' se abre automáticamente o por alguna interacción inesperada.
3 Revisar los pasos previos del test para identificar si alguna acción podría estar abriendo el modal.
4 Reproducir el spec fallido localmente: `TARGET_ENV=production TARGET_CLIENT=br-gs64 MODE=only SPEC=gs64_smoke_tasas npm run test`
